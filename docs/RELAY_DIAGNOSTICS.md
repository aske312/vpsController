# Проверка Relay в ROUTES

Нужны PRO с диагностическими тестами и Agent 1.3. После установки обновлений вручную откройте Сеть → Адреса → нужный Relay. В боковой панели «Проверить подключение» выберите маршрут и существующее подключение нужного протокола.

## Проверка с VPS

Нажмите «Проверить с VPS» и дождитесь окончания операции. PRO запускает отдельный протокольный клиент через выбранный вход Relay. Проверяются полное видео W3C Sintel (4 372 373 байта, SHA-256) и три запроса перемотки, два параллельно. HTTP 200 и открытый порт отдельно не считаются успехом.

Медиапуть: **VPS → Relay → VPS или CDN → сайт с видео**. Для Mihomo берётся фактический экспорт выбранного устройства с сохранением TLS/SNI. Неоднозначный экспорт или отсутствие подходящего ядра дают неподтверждённый результат, без замены Relay прямым IP VPS.

Для WireGuard и AmneziaWG создаётся отдельный peer с новым ключом и свободным IP. Рабочие peer и сохранённые профили не меняются. Новый IP учитывается распределителем обычных подключений. Peer удаляется при успехе и ошибке; отдельный таймер обеспечивает очистку после сбоя процесса. Поддерживаются существующие Mihomo WG/AWG и Direct WG/AWG через Relay.

## Проверка с компьютера

1. Нажмите «Тест с устройства». На подготовку и выполнение отводится 10 минут.
2. Дождитесь готовности, скачайте ZIP и распакуйте его на проверяемом компьютере.
3. Запустите `python runner.py --core "ПУТЬ_К_ЯДРУ"`. В README комплекта указан формат ядра: Mihomo, Xray или sing-box. Нужны Python 3 и curl. Ядро утилита не скачивает.
4. Загрузите созданный `result.json` в ROUTES. PRO сопоставит UDP-наблюдения сторон, покажет результат и удалит временные ресурсы.

Комплект содержит конфигурацию подключения — обращайтесь с ним как с приватным профилем. В него не входят IP origin VPS, административный пароль, токен Agent или адрес обратного подключения к PRO. Утилита не переключает системный VPN, DNS или TUN.

Для проверки физической сети используйте Mihomo и параметр `--interface`, например `--interface Ethernet` на Windows. На Linux привязка UDP к интерфейсу может требовать root. Без явного интерфейса используется обычная маршрутизация ОС, включая включённый VPN. Пример: `python runner.py --core "C:\Tools\mihomo.exe" --interface Ethernet`.

Для отмены нажмите «Отменить тест». При закрытии браузера сессия завершится по сроку: временный peer, диагностический порт, правило firewall и серверная копия комплекта удаляются. Очистка предусмотрена при остановке рабочего процесса и после перезапуска PRO. Ошибка очистки показывается отдельно.

Медиарезультат сообщается клиентской утилитой и не является независимой аттестацией приложения. UDP-наблюдения сопоставляются с Agent и VPS. Тест не записывает приложению статус совместимости и не проверяет физический iPhone, YouTube или все правила полного профиля.

## Потери и обратный трафик

Вместе с медиатестом проводится отдельное UDP-измерение: 100 подписанных пакетов по 1200 байт, без повторных отправок, окно до 5 секунд. Путь: **отправитель → Relay → VPS → Relay → отправитель**. Отправителем служит VPS или проверяемый компьютер.

PRO сопоставляет номера пакетов на трёх сторонах и показывает потери отдельно для четырёх направлений, локальные отбрасывания и RTT. Диагностический UDP-порт временный, он использует те же Relay и VPS, но отличается от порта зашифрованного протокола. Его результат не измеряет внутренние потери QUIC/WireGuard и не доказывает причину блокировки конкретного протокола. При недоступности измерения выводится «не подтверждено».

На VPS на время теста добавляется правило INPUT только для UDP-порта измерителя и IP выбранного Relay, затем удаляется. Ограничения внешнего firewall хостера этим правилом не обходятся. Недоступный внешний UDP-порт может стать причиной отказа именно диагностического измерения.

Agent отдельно показывает активные сессии, у которых после отправки более 5 секунд не наблюдается обратного трафика. Это наблюдение транспорта, а не доказанная ошибка: односторонний трафик и keepalive могут не требовать ответа. Подтверждение обмена дают сами тесты.

## Актуальность и обновления

Порт, серверный тест и клиентский тест показаны раздельно с временем и ошибками. При изменении настроек или через час результат считается неподтверждённым. Счётчики Agent сбрасываются при перезапуске.

Автообновление Agent из GitHub раз в сутки включено по умолчанию начиная с 1.2; старым установкам нужна однократная штатная переустановка. Обновление перезапускает Agent и может прервать активные соединения. Обновление PRO само по себе не переустанавливает удалённые Agent.

Начиная с Agent 1.4, PRO показывает в подробностях Relay доступную версию и кнопку «Обновить Agent», когда установленная версия старее опубликованной. Сведения о релизе кешируются до пяти минут; при недоступном GitHub кнопка не предлагается. Команда устанавливает только опубликованный CI-пакет с подтверждённой контрольной суммой. Установка той же или более старой версии запрещена.

PRO показывает очередь, выполнение, ошибку или завершение после подтверждения работающей версии. Потеря ответа не вызывает повторную отправку команды. Ручное обновление работает и при выключенном суточном автообновлении, не меняя эту настройку. Сертификат, ключи, токен и маршруты сохраняются. Во время активного клиентского теста обновление недоступно.

Agent 1.3 и старше ещё не принимают эту команду: первоначальный переход на 1.4 выполняется вручную штатным установщиком либо суточным updater (если включён). После этого последующие новые версии можно устанавливать кнопкой из PRO.

## Подтверждение очистки

Если связь с Relay потеряна при удалении диагностического порта, ROUTES показывает ожидание подтверждения. Agent самостоятельно закрывает порт по сроку; PRO повторно читает состояние, не повторяя неизвестно завершившуюся команду удаления. Временный peer и локальное правило firewall очищаются независимо через systemd.
