# Устойчивое выполнение чата Nodera

Сообщения панели отправляются в `POST /api/assistant/requests` с уникальным
`request_id`. Ответ `202` подтверждает приём задачи, а не успешную генерацию.
Обычный режим показывает готовый ответ целиком. Отдельная опция «Настройки чата →
Потоковый ответ» выключена по умолчанию и сохраняется для вкладки браузера.

## Задачи и восстановление

- `GET /api/assistant/requests/{id}` возвращает состояние и сохранённый результат.
- `GET /api/assistant/requests/{id}/stream` передаёт снимки состояния через SSE,
  с heartbeat каждые 10 секунд и переподключением по тому же ID.
- Оба GET используют обычную авторизацию панели. `telegram_id` выбирает контур;
  права на чат проверяются при отправке, выполнении и чтении. ID не заменяет авторизацию.
- Повторный POST с тем же ID и тем же содержимым читает прежнюю задачу;
  изменение содержимого или контура не запускает вторую генерацию.
- Отдельная transient systemd-служба переживает завершение HTTP-запроса и рестарт
  API. После перезагрузки ОС или гибели worker результат может быть неизвестен:
  задача не отправляется провайдеру повторно. Состояние `unknown` не является успехом.
- В sessionStorage сохраняется только ID в контуре сессии панели и пользователя.
  При перезагрузке вкладки интерфейс читает эту задачу. При длительном обрыве
  доступна кнопка «Восстановить ответ»; повторного POST она не делает.
- Вопрос, входные данные и результат хранятся приватно в
  `{DATA_DIR}/assistant/requests/` (каталоги 0700, JSON 0600). Входные вложения
  удаляются из записи при завершении задачи. Результаты доступны 24 часа;
  истёкшие записи очищаются при приёме следующих задач. Это временное хранилище
  доставки, отдельное от отключаемой долговременной памяти диалогов.
- Лимиты: 16 незавершённых задач, 3 на пользователя, 256 записей и около 96 МиБ
  входного хранилища. На провайдера одновременно выполняется один запрос;
  глобально — до двух через общие файловые блокировки, включая прежний API чата.

## Потоковый режим и ошибки

Требуется AI-agent 1.23.0 / Nodera 1.16.0. Панель показывает доступность опции
по установленной версии; обновление одной панели не обновляет необязательный runtime.

При включении провайдер получает `stream: true` и
`stream_options: {include_usage: true}`. Текст выводится частями. Аргументы
инструментов собираются полностью; незавершённый поток не запускает частичный
вызов. Финальные данные usage используются только при их наличии.
Провайдер без поддержки streaming возвращает явную ошибку: скрытого повторного
запроса без streaming нет. Опцию можно выключить для следующего сообщения.

Таймауты нового runtime: подключение 10 с, передача 20 с, отсутствие входных данных
120 с; общий срок runtime 240 с. Ожидание общей блокировки — до 90 с,
независимая служба ограничена 6 минутами. SSE-соединение закрывается через 5 минут,
но интерфейс продолжает чтение прежней задачи. Старый установленный runtime
продолжает использовать свои ограничения до штатного обновления Nodera.

Ошибки различают DNS, TLS, подключение, ожидание данных, передачу, обрыв потока,
HTTP-код провайдера, некорректный ответ и общий таймаут. Запись задачи содержит
модель, длительность и ID; в Observability записываются только безопасные метаданные
результата с `kind=chat_job`, без текста запросов, ответов и секретов.
После начала отправки запроса автоматического повтора генерации нет.

Старый `POST /api/assistant/chat` сохранён для совместимости. Telegram-интерфейс
сохраняет свой существующий механизм доставки; новый протокол фоновых задач
используется чатом панели. Streaming между панелью и браузером использует fetch
с заголовком Authorization, а не передачу секретов в URL.
