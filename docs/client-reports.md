# Отчёты клиента подписки · v1

Заготовка серверного протокола обратной связи. Отправка из NoderaClient пока
не реализована. Клиент может обнаружить поддержку по заголовку подписки
`X-Nodera-Reports-Version: 1`. Старые клиенты продолжают получать прежний YAML.

`POST /s/{token}/reports` (также `/api/mihomo/subscriptions/{token}/reports`).
Авторизация: ссылка подписки и те же `X-Device-ID` / `X-HWID`, `X-Client-Name`,
`X-Device-OS`, `User-Agent`, с которыми устройство уже получило подписку.
Ссылка устройства действует только для его HWID. Отчёт не регистрирует устройства.
Истёкшие подписки, исчерпанная квота и сервисный режим запрещают запись.

```json
{
  "version": 1,
  "report_id": "bb9f60da-c44d-4e78-b5d8-cef5e897c1cf",
  "session_id": "abec7f0a-d2f8-42b3-af13-c9835ef3a306",
  "observed_at": "2026-11-14T12:00:00Z",
  "client_version": "0.0.4",
  "counters": {"upload": 1234, "download": 5678, "connections": 2},
  "events": [
    {"time": "2026-11-14T11:59:59Z", "event": "traffic", "delta_upload": 24, "delta_download": 128}
  ]
}
```

Счётчики — наблюдение текущей сессии ядра: байты upload/download, число активных
соединений. Неизвестные значения передаются как `null` или отсутствуют.
При перезапуске ядра клиент должен сменить `session_id`. Сервер не суммирует
снимки, не использует их для квот и не считает подтверждением доступности сети.
Времена содержат часовой пояс; срок хранения считается по времени приёма сервера.

Формат основан на `nodera/journal.py` и `nodera/connection_journal.py` в
NoderaClient: события `opened`, `traffic`, `closed`, `time`, `upload`, `download`,
`delta_upload`, `delta_download`. Клиент должен проецировать записи на эти поля.
Свободные `message`, host/IP, process, route, rule, URL подписки, ключи и сырые
журналы `events.jsonl` / `network.jsonl` не принимаются. Лишние поля отвергаются.

Успех: `{"version":1,"accepted":true,"duplicate":false}`. Повтор того же
`report_id` в пределах устройства возвращает `duplicate:true` без новой записи;
для повтора нужно сохранить исходный ID. Новый отчёт — не чаще раза в 15 секунд,
иначе 429 с `Retry-After: 15`. Не более 100 событий в отчёте. Неверная схема — 422,
неизвестная подписка — 404, чужое устройство — 403, запись временно закрыта — 409.

Хранилище: `mihomo/client-reports/reports.sqlite3` в каталоге данных. При приёме
удаляются записи старше 7 дней, сохраняются последние 100 отчётов устройства
и максимум 10 000 суммарно. Это отдельные недоверенные клиентские наблюдения;
профили, серверный учёт трафика и настройки не меняются. Чтение/интерфейс отчётов
и отправка из клиента относятся к следующему этапу интеграции.
