# Диагностика операций и кода в Nodera

Новые инструменты доступны с AI-agent 1.22 / Nodera 1.15 и соответствующей
версией приложения. Для существующего компонента нужно штатное обновление.

## Найти операцию без ID

`operation_inventory(action="protocol-update:nodera", outcome="error", minutes=10080)`
возвращает ID, источник, действие, исходные state/result, область проверки,
последний этап и код ошибки. Каждый результат содержит вызов `operation_timeline`
для продолжения. Фильтры: action (часть имени), source (system/mihomo/cdn),
outcome (active/success/error/unknown/cancelled/skipped), minutes, limit и offset.

По умолчанию фоновые проверки ai-catalog/runtime-check скрыты. Для их просмотра
используйте `include_checks=true` либо явный action. Чтение ограничено 2000
сохранёнными записями каждого источника и общим бюджетом 8 МБ; coverage показывает сокращение и пропуски.
next_offset листает найденные результаты. Если запись удалена по сроку хранения,
отсутствие ID не доказывает отсутствие операции.

`operation_timeline(operation_id="<32 hex>", include_journal=true)` возвращает
этапы, результат родительской операции, HTTP409 с request/trace ID, текущий
указатель принятой операции, recovery-маркеры и текущее наблюдение worker.
Отсутствующий collected-unit не переписывает исторический результат. Наличие
recovery-маркера или процесса само по себе не доказывает владение блокировкой.

В OPERATIONS ID виден в карточке; кнопка «Контекст для Nodera» копирует ID и
сведения для разбора. Состояние операции, результат и результат этапа разделены.
`succeeded + passed` и `succeeded + success` означают успешное завершение;
`running + passed/failed` относится к этапу ещё работающего родителя. Явный unknown
остаётся неизвестным. Неизвестный код результата не превращается в успех или ошибку.
Успех каталога моделей не подтверждает генерацию ответа AI.

## Инструменты разработчика

`developer_inspect` поддерживает:

- `inventory(path="api")`: список исходников, offset для следующей страницы.
- `search(path="src", query="operationOutcome")`: буквальный поиск и строки совпадений.
- `read(path="api/application_operation.py", line=300, lines=80)`: нумерованный фрагмент.
- `symbols(path="api/application_operation.py")`: функции/классы и диапазоны строк Python AST.
- `dependencies()`: наблюдаемые версии runtime, объявления Node-зависимостей с установленными версиями и выбранные пакеты ОС (systemd/OpenSSL/libc/сеть/CA/SSH).

Изучается установленный код, а не другая ветка GitHub. Ответ содержит commit
сборки (если известен), SHA256 прочитанного файла, номера строк и сведения
об усечении/редакции. При смене сборки во время чтения это отмечается.
Python разбирается как AST без импорта или выполнения. Для TypeScript/JS
доступны чтение и поиск. requirements.txt можно читать в каталогах исходников.
Неизвестная версия зависимости не заменяется нулём; локальный инвентарь не является
проверкой CVE или доказательством функциональной исправности.

Доступны исходники api/src/app/scripts/protocol-images и публичные документы,
а также известные корневые manifests. Пути относительные; абсолютные пути,
traversal, symlinks/hardlinks, окружение, runtime/data, node_modules/vendor и приватные
каталоги закрыты. Произвольные JSON-конфиги не читаются. Размер файла ограничен
2 МБ, поиск — 4 МБ прочитанных данных, вывод — ограниченным фрагментом.
Известные секреты редактируются. Содержимое кода/комментариев остаётся недоверенным.

Инструмент не принимает shell/код модели, не меняет файлы, не запускает тесты
или установку пакетов. Версии снимаются фиксированными запросами метаданных.
Требуются diagnostics + server_read + terminal_read;
для истории и таймлайна — diagnostics + server_read + logs_read.
Инструменты доступны только через контур vps-controller-mcp, не через Mihomo.
Вывод о баге нужно связывать с конкретным commit/файлом/строками и отличать
гипотезу по коду от подтверждённого воспроизведения.
