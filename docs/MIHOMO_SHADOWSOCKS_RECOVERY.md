# Защита Mihomo/Shadowsocks от исчерпания ресурсов

Наблюдавшийся инцидент: процесс `ss-server` достиг мягкого лимита 1024 дескриптора и бесконечно выводил `accept: Too many open files`. Сам процесс и обработка журнала занимали почти два CPU. `Restart=on-failure` не помогал, поскольку процесс не завершался.

Исправление находится в локальном репозитории; само по себе оно не меняет работающий VPS.

## Поведение приложения

- Для экземпляров Mihomo/Shadowsocks установлен мягкий лимит 16384 дескриптора и жёсткий 524288.
- Сервер запускается через `guard.py`. При сообщении об исчерпании дескрипторов, памяти или сетевых буферов обёртка завершает только свой экземпляр и возвращает ненулевой код. systemd повторяет запуск через 30 секунд.
- Обычные журналы ограничены 20 фрагментами за 10 секунд. Ошибки исчерпания ресурсов проверяются даже после достижения этого лимита. Размер читаемого фрагмента ограничен 4096 байтами.
- Остановка из панели завершает также дочерний процесс и не превращается в запрос автоматического восстановления. При зависании завершения дочерний процесс принудительно останавливается через 3 секунды.
- Профильные ключи, пароли, порты и настройки не меняются. Другие протоколы не перезапускаются.

Защита подключена к установке компонента и обычному обновлению приложения, в том числе для уже установленных компонентов без созданных профилей. При первом применении обновления работающие экземпляры Shadowsocks будут перезапущены для перехода на защищённый запуск. Последующие обновления с неизменной защитой повторно их не перезапускают. Удаление компонента удаляет и его защиту.

## Ограничения

Это защита от наблюдавшегося бесконечного цикла ошибок, а не исправление сетевого клиента или внутренних таймеров shadowsocks-libev. Она не доказывает и не устраняет причину накопления пустых TCP-соединений. При аварийном восстановлении сессии проблемного экземпляра разрываются и клиент должен переподключиться. Если источник продолжает исчерпывать ресурсы, восстановление может повторяться.

Регрессионные тесты запускают реальные дочерние процессы: проверяют бесконечный поток ошибок, ограничение обычных журналов, распознавание ошибки после исчерпания бюджета журнала, коды завершения и остановку без оставленного процесса. Отдельный тест реального `EMFILE` через `RLIMIT_NOFILE` выполняется только на Linux; на Windows он пропускается.
