# Relay Agent

Standalone TCP/UDP Relay для PRO. Код и канал обновлений находятся в ветке `agent`.

## Обновления

С версии 1.2 автообновление включено по умолчанию. Таймер `vps-control-relay-update.timer` проверяет GitHub раз в сутки со случайной задержкой до часа. Пропущенная проверка выполняется после включения сервера. Обновление перезапускает службу, поэтому текущие соединения могут прерваться.

Пакет `relay-agent.tar.gz` публикуется в prerelease `agent-latest` только после успешных проверок, включая установку и откат в изолированной Linux-среде. Updater проверяет SHA-256 из метаданных GitHub, состав архива и синтаксис файлов. Используется фиксированный репозиторий `aske312/vpsController`. Доверие к обновлению основано на HTTPS GitHub и правах публикации этого репозитория; отдельной подписи пакета нет.

При сбое запуска установщик возвращает прежние файлы Agent. Токен, сертификат, настройки и сохранённые маршруты не заменяются. Если GitHub недоступен или контрольная сумма не совпала, установка не запускается. Обновления выполняются под общей блокировкой с ручной установкой.

Старые Agent 1.0/1.1 не имеют updater: для включения механизма нужно один раз штатно переустановить Agent из ветки `agent`. Последующие обновления автоматические.

Проверить состояние:

```bash
systemctl status vps-control-relay-update.timer
journalctl -u vps-control-relay-update.service
cat /etc/vps-control-relay-agent/update-status.json
```

Отключить обновления, сохранив настройку при переустановке:

```bash
sudo python3 - <<'PY'
import json
from pathlib import Path
Path('/etc/vps-control-relay-agent/updates.json').write_text(json.dumps({'enabled': False}))
PY
```

Для включения используйте `True`. Ручная проверка: `sudo systemctl start vps-control-relay-update.service`.

## Связь с PRO и ROUTES

API v1 совместим с прежними PRO. Новые необязательные поля:

- `/v1/status`: `updates` — настройка и результат обновления; `address_checks` — результаты DNS.
- `/v1/routes`: `diagnostics` — число UDP-пакетов в обе стороны, локальных отбрасываний, ошибки по типам и время последнего отправления/ответа/ошибки. Счётчики относятся к текущему запуску службы.

Токен API отправляется только после проверки закреплённого сертификата. В диагностике нет содержимого трафика, клиентских адресов, ключей или произвольных текстов сетевых исключений. Счётчики отправки означают передачу в сокет, а не подтверждение доставки пакета; локальные отбрасывания не измеряют потери на всём сетевом пути.

Имена из hostname и локальных конфигураций сначала считаются кандидатами. Обычный домен предлагается для клиентов только после DNS-проверки на адреса самого Relay. Явно настроенные CDN-домены проверяются отдельно: публичный DNS сохраняет их как `dns_only`, без утверждения о работоспособности CDN. При временной ошибке DNS домен может исчезнуть из списка новых адресов; существующие подключения и пересылки не переписываются.

В совместимой версии PRO: ROUTES → раскрыть Relay → «Перенаправления Relay» → выбрать существующее подключение → «Проверить видео с VPS». PRO запускает изолированный протокольный клиент без прямого fallback, проверяет полное видео по хешу и три Range-запроса. HTTP 200 отдельно не считается успехом. В ROUTES сохраняются время, результат и причина. При изменении конфигурации или по истечении часа результат считается неподтверждённым.

Проверка с VPS не доказывает доступность из каждой клиентской сети. Для Mihomo используется фактический экспорт подключения с TLS/SNI. В PRO есть тест с устройства: комплект запускается локальной утилитой, результат загружается обратно в ROUTES. Для WG/AWG PRO создаёт и удаляет отдельный временный peer с независимой очисткой по сроку, не используя действующий peer.

## Диагностика 1.3

Agent 1.3 объявляет capability `udp-measurement-v1`. За pinned API доступны `PUT/GET/DELETE /v1/measurements/{32-hex-id}`. Это временный UDP-порт из диапазона 20000–20999, связанный с существующим маршрутом; постоянные routes/revision не меняются. Одновременно допускаются два измерителя, срок — до 1200 секунд. Просроченный измеритель автоматически закрывается. Повторный PUT того же ID не продлевает срок и не меняет параметры.

PRO задаёт адрес временного приёмника, ключ HMAC и срок. Принимаются только 100 уникальных подписанных пакетов по 1200 байт; дубликаты, неверные подписи и посторонние пакеты игнорируются. Ответ возвращается только отправителю соответствующего запроса. Нагрузка и размеры ограничены, ключ не возвращается в API-статистике. Клиент получает только адрес Relay и тестовые параметры; IP origin в комплект не входит.

Счётчики ingress/forward/reply/egress позволяют PRO сопоставить наблюдения клиента, Relay и VPS, определить потери по участкам и RTT. Это отдельный диагностический UDP-путь между теми же узлами, не расшифровка протокольного трафика. Медиатест выбранного протокола проводится отдельно. Клиентский медиарезультат является сообщением утилиты, UDP-путь имеет дополнительные наблюдения Relay/VPS.

`diagnostics.return_state` показывает `idle`, `waiting`, `flowing` либо `no_return`; `no_return_sessions` — число активных сессий с отправкой без ответа более 5 секунд. Это не автоматическое доказательство поломки: нормальный односторонний трафик также возможен. Пакет обновления сохраняет прежний состав из семи файлов, чтобы updater версии 1.2 мог принять обновление до 1.3.
